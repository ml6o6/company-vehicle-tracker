# Сервис учета автомобилей организации

## Назначение

Сервис для учета автопарка и планирования служебных поездок. Консольная версия ПР3 дополнена веб-интерфейсом на Django 5.2. В ПР6 начат переход на Django-шаблоны.

Консольная версия позволяет:

- просматривать и добавлять автомобили и водителей;
- находить автомобили по модели или госномеру;
- проверять пассажирскую вместимость;
- отбирать и сортировать автомобили по вместимости;
- проверять доступность автомобиля и водителя на дату;
- рассчитывать топливо и проверять срок ТО перед поездкой;
- создавать, отменять и просматривать поездки;
- сохранять данные между запусками.

В браузере доступны списки и карточки автомобилей и поездок, а также занятость автомобиля на текущую дату.

## Используемые технологии

- Python и Django 5.2;
- HTML, CSS и Bootstrap 5.3;
- Django Template Language (DTL);
- JSON для данных предметной области;
- pytest и flake8.

## Целевая аудитория

Диспетчеры и сотрудники, отвечающие за служебный автопарк организации.

## Предметная область

Основные объекты проекта:

- автомобиль;
- водитель;
- поездка;
- обслуживание.

Диспетчер назначает автомобиль и водителя на определенную дату. Автомобиль и водитель не могут участвовать в двух активных поездках в один день.

Отмененная поездка остается в истории, но освобождает дату и зарезервированный пробег до ТО. Все активные поездки считаются запланированными; фактический пробег автомобиля автоматически не изменяется.

## Основные сущности

Каждый класс имеет конструктор `__init__()` и метод `__str__()` для вывода понятного описания объекта.

### Car — автомобиль

Хранит данные служебного автомобиля и его обслуживания.

Основные атрибуты:

- `id` — идентификатор автомобиля;
- `model`, `plate` — модель и госномер;
- `capacity` — число пассажирских мест без водителя;
- `mileage` — текущий пробег;
- `fuel_consumption` — расход топлива на 100 км;
- `maintenance` — объект `Maintenance` с данными ТО.

Основные методы:

- `is_suitable_for()` — проверка вместимости;
- `calculate_fuel()` — расчет топлива на маршрут;
- `service_remaining()` — остаток пробега до ТО;
- `get_service_status()` — проверка необходимости ТО;
- `from_data()` — создание автомобиля из записи JSON.

### Driver — водитель

Представляет водителя с допуском к автомобилям организации.

Основные атрибуты:

- `id` — идентификатор водителя;
- `name` — ФИО;
- `has_permission` — наличие допуска.

Основные методы:

- `can_drive()` — проверка допуска;
- `get_driver_status()` — описание допуска и занятости;
- `from_data()` — создание водителя из записи JSON.

### Trip — поездка

Связывает автомобиль и водителя с датой и параметрами маршрута.

Основные атрибуты:

- `id` — идентификатор поездки;
- `car`, `driver` — объекты `Car` и `Driver`;
- `trip_date` — дата поездки;
- `distance` — расстояние полного маршрута;
- `passengers` — число пассажиров;
- `is_cancelled` — признак отмены.

Основные методы:

- `cancel()` — отмена поездки без удаления из истории;
- `calculate_fuel()` — расчет топлива через связанный автомобиль.

### Maintenance — обслуживание

Хранит данные последнего ТО и межсервисный интервал автомобиля.

Основные атрибуты:

- `last_mileage` — пробег последнего ТО;
- `interval` — интервал между обслуживаниями.

Основные методы:

- `remaining()` — расчет остатка пробега до ТО;
- `get_status()` — проверка срока ТО перед маршрутом.

## Страницы веб-интерфейса

| URL | View-функция | Назначение |
| --- | --- | --- |
| `/` | `homepage.views.index()` | Главная и навигация |
| `/cars/` | `cars.views.cars()` | Список автомобилей |
| `/cars/<int:car_id>/` | `cars.views.car_detail()` | Карточка автомобиля и занятость сегодня |
| `/trips/` | `trips.views.trips()` | Список активных и отмененных поездок |
| `/trips/<int:trip_id>/` | `trips.views.trip_detail()` | Карточка поездки с автомобилем и водителем |

На первом этапе ПР6 главная и страницы автомобилей используют `render()`
и наследуют `templates/base.html` с блоками `title` и `content`.
Данные передаются в шаблоны через контекст. Список использует
`{% for %}`, `{% empty %}` и `{% include "cars/includes/car_card.html" %}`.
Карточка обрабатывает отсутствие автомобиля через `{% if car %}`
с ответом 404. Ссылки формируются через `{% url %}` с пространствами имен.

Страницы поездок и общий обработчик 404 пока используют `page()`.
Их перенос, фильтры и статические файлы относятся ко второй части ПР6.
Неизвестный объект возвращает 404. Для неизвестного URL обработчик
`page_not_found()` подключен в корневом `urls.py` и используется при
`DEBUG=False`.

## Основные операции консольной версии

### Работа с автомобилями

- добавление и просмотр автомобилей;
- поиск по модели или госномеру;
- проверка и отбор по вместимости;
- сортировка по вместимости;
- контроль срока ТО и расчет топлива.

### Работа с водителями

- добавление и просмотр водителей;
- проверка допуска и занятости на дату.

### Работа с поездками

- предварительная проверка подготовки поездки;
- создание поездки со свободными автомобилем и водителем;
- отмена с сохранением записи в истории;
- просмотр активных и отмененных поездок.

При создании проверяются занятость участников, допуск водителя, число пассажирских мест и остаток до ТО. Суммарный пробег активных поездок не должен достигать порога обслуживания.

## Хранение данных

Данные хранятся в JSON-файлах:

- `data/cars.json`;
- `data/drivers.json`;
- `data/trips.json`.

При загрузке записи преобразуются в объекты `Car`, `Driver` и `Trip`. Данные обслуживания создают объект `Maintenance` внутри автомобиля.

В памяти поездка хранит ссылки `car` и `driver` на объекты участников. В JSON сохраняются их идентификаторы `car_id` и `driver_id`, а также признак `is_cancelled`.

## Назначение модулей

- `manage.py` — команды управления Django.
- `vehicle_site/` — настройки, корневые маршруты и точки входа сервера.
- `homepage/` — главная через шаблон, временный `page()` и обработчик 404.
- `cars/` — список и карточка автомобиля через шаблоны и контекст.
- `trips/` — список и карточка поездки.

### main.py

Точка входа: отображает меню, получает данные пользователя и вызывает операции проекта.

### models/cars.py и models/drivers.py

Содержат классы `Car` и `Driver` и функции работы с их коллекциями.

### models/trips.py

Содержит класс `Trip`, проверку доступности, создание и отмену поездок.

### models/maintenance.py

Содержит класс `Maintenance` и проверки срока ТО.

### storage.py

Загружает объекты из JSON и сохраняет их данные, преобразуя ссылки на участников в идентификаторы.

### utils.py

Содержит проверки значений и функции безопасного ввода чисел, дат и допуска водителя.

### tests/

Содержит автоматизированные тесты. `pytest.ini` настраивает их запуск из корня проекта.

## Требования

- Python 3.10 или новее;
- Django 5.2 (для Python 3.14 — от 5.2.8);
- pytest;
- flake8.

Установка зависимостей:

```powershell
pip install -r requirements.txt
```

## Запуск приложения

Команды выполняются из папки `vehicle-accounting` с выбранным окружением `.venv`.

Веб-версия:

```powershell
python manage.py migrate
python manage.py check
python manage.py runserver
```

Откройте `http://127.0.0.1:8000/`. Миграции создают только служебные
таблицы Django; данные автомобилей и поездок хранятся в JSON.

Консольная версия:

```powershell
python main.py
```

## Тестирование

```powershell
pytest -v
```

Тесты проверяют:

- создание объектов, их атрибуты и методы;
- строковое представление `__str__()`;
- поиск, отбор и сортировку автомобилей;
- создание и отмену поездок, доступность участников;
- связи поездки с автомобилем и водителем;
- загрузку и сохранение JSON;
- обработку ошибочного ввода и ошибок записи;
- веб-маршруты, карточки и статусы доступности;
- страницы 404, навигацию и экранирование данных в HTML;
- наследование шаблонов, включаемую карточку и передачу контекста.

Веб-тесты используют временные JSON-файлы и Django Test Client; рабочие данные и база не меняются.
